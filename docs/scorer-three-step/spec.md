# Spec: 认人页三步引导流程——判队伍 / 并簇认人+改名 / 按人逐球核对

## Objective

现状问题（2026-08-15 立哥）：认人页功能堆平铺，没有流程引导；缺两个
关键环节——页内改真名、按球员逐球核对。立哥定的认人流程：

1. **第一步判队伍**（拖拽改队，已具备）
2. **第二步合并簇、认人、改名**（合并已具备；缺页内改真名）
3. **第三步按球员逐球核对归属**，判错可改归别人（现状是全量逐球列表，
   缺按人核对模式）

本功能做五件事：

1. **三步引导标题条**：名单区/簇区/逐球区上方各加一步标题 + 一句话
   指引（现有区块顺序恰好契合流程，不重排）
2. **页内改真名**：队伍区每个队员按钮旁加"改名"钮，弹输入框改/清空
   真名（`标签=真名` 即时刷新）；存 localStorage 独立键，导出 roster
   的 name 字段跟随。**标签不给改**（归属键，级联风险，立哥已确认）
3. **按人核对模式**：核对区顶部加"核对对象"行——全部（=现状）/
   各已归属球员 / 未归属；选球员后逐球区只显示其名下球，判错点另一
   球员按钮即改归（复用现有 assign，自动记 touched、自动前进）
4. **删簇**（2026-08-15 立哥：簇6 整簇裁图是酒瓶广告——轨迹链漂静物
   的误分组）：每个显示组行加"删除"钮，confirm 后把该组从簇区移除。
   **只移除分组视图**：簇内进球仍在逐球区、归属 marks/touched 一律不动
   （裁图错不耽误第三步看视频终裁归属）。墓碑存 clState 新增 `deleted`
   子键，刷新/重生成页面后仍隐藏；找回只能清站点数据（手册注明）。
   demo 里"从内联 CLUSTERS 数组剔除簇6"的手工 hack 由本功能取代。
5. **逐球区裁图/视频并排定高不定宽**（2026-08-15 demo 验证中立哥实测
   反馈）：裁图与视频包进 `#review` flex 容器（`align-items: flex-start`），
   两者 `height: 68vh; width: auto`——顶端对齐、翻球不跳高、无黑边。
   教训记录：①裸内联按基线对齐 → 图/视频一高一低；②固定框 +
   object-fit 留边 → 黑边大片、图视间大片空白（立哥实测"黑色空格"）
   证伪；③**悬停放大恢复保留**（点击放大因 CSS 优先级失效证伪；悬停
   浮层规则须压过 `.cluster-row img.rep` 与 `#review #crop` 尺寸限制）

成功标准：

- 三步标题条渲染；无 --clusters 时页面行为同现状（向后兼容）
- 改名：队伍区按钮文字即时变 `标签=真名`，导出 roster name 跟随，
  刷新不丢；清空真名回退纯标签
- 按人核对：选球员后 ITEMS 过滤为其名下球；改归后球离开当前过滤集
  并前进；切人/切回全部/跳到未归属正常；进度显示"第 x/y 个（人名）"
- 删簇：confirm 后组从簇区消失，刷新/重生成后仍隐藏；组内球仍在
  逐球区、marks/touched 不动
- 导出 roster.json schema 不变；touched 规则不动（核对改归照常记 touched）
- pytest 全绿、ruff 干净；四件套齐全

## Tech Stack

- 纯前端：`scripts/gen_scorer_page.py` 的 `_HTML` 模板（CSS + JS），
  零 Python 逻辑变更、零新依赖；roster 导出契约不动

## 数据契约

### 改名（新 localStorage 键）

`scorer_<session>_names`（平铺对象 `{ tag: name }`）：

- 读写沿用 save() 读回合并写模式 + JSON 解析失败回退空对象
- **清空真名 = 写空串不删键**（`ovr[tag] = ""`）——读回合并写会复活
  本地已删的键（saveClState 前科），删键语义不可用它；加载时
  空串视为无真名
- 加载时应用回 PLAYERS（`p.name = ovr[p.tag] || ""`，在首次渲染前）
- 改名入口：队伍区每个队员按钮旁的小"改名"钮（簇区/弹条按钮不加，
  防拥挤）；点了 `prompt("真名（空=清除）", 现值)`：
  - 输入非空 → `p.name = 输入`、`ovr[tag] = 输入`
  - 输入空串 → `p.name = ""`、`ovr[tag] = ""`
  - 取消（null）→ 不动
- 改名后重渲染（按钮文字 tag=name 全局生效：队伍区主行/兜底行/簇区/
  弹条**四处**按钮文字都读 p.name，改内存值即全刷）
- 导出：`players = PLAYERS.map(...)` 读内存值自动跟随；自动补录分支
  （名单外自由输入 tag）沿用现逻辑不动（改名入口只在队伍区名单按钮旁，
  名单外 tag 无入口，ovr 里不会有它们的记录）

### 按人核对（新 localStorage 键）

`scorer_<session>_review`（平铺对象 `{ "target": ... }`；"全部"=
`target` 为空串，"未归属"= 特殊值 `"__none__"`；**切回全部/清除 =
写空串不删键**，理由同 names 键的读回合并写复活坑。自由输入框拒绝
`__none__` 这个值，防撞特殊值——一行守卫）：

- 核对对象行渲染在逐球区上方（第三步标题条下）：
  `核对对象：[全部] [黑21=大斌] … [未归属]`
  ——球员按钮只列**当前 marks 里有归属球**的 tag（每次渲染动态算；
  含自由输入的名单外 tag，无 name 纯显示 tag，属正常）
- 选中态 = 过滤集（可见集，ITEMS 本体不动）：
  - 全部 → 现 ITEMS 全量
  - 某球员 → ITEMS 中 `marks[key] === tag` 的子集
  - 未归属 → `!marks[key]` 的子集
- **可见集抽象**：新增 `visible()` 返回过滤集数组；cur 索引、进度、
  翻页、S 跳过、跳到未归属全部作用于可见集。**现有 ITEMS 直接引用点
  全部改读可见集当前项**：show() 本体、renderPlayers 两处 sel 高亮
  （含"其他"兜底行）、keydown E 键 `prefill_tag`、accept 钮
- **assign 前进语义按模式分支**（assign 被数字键/E 键/accept/簇区/
  弹条共用，勿统一改）：
  - 全部模式 = 现状（跳下一个未归属球，全局 findIndex）
  - 按人/未归属模式 = 改归后球离集，落在原索引位置的新的当前项
    （过滤集 [i] 即下一个），到尾则停末尾
- **空可见集渲染空态**（"无球/核对完毕"提示行），**不得**像现状
  `if (!ITEMS.length) return;` 那样早退停在旧画面：
  - 按人模式改归后集变空 → 提示"此人核对完毕"并自动切回全部
  - 未归属集变空 → 提示"未归属清零"并切回全部
  - 进入即空（持久 target 的球被 roster/marks 变化清空）→ 回退全部
- 进度行显示 `第 x/y 个（核对：郑翔）`（核对对象显示
  `tag`（有真名则 `tag=真名`）；全部模式不显示该后缀）
- **位置持久按核对对象分键**：`scorer_<session>_pos_<target>`（全部
  沿用旧 `_pos` 键兼容存量；target 用 URL 安全的 encodeURIComponent）
  ——不同核对对象下同一索引指向不同球，不分键会错位
- 启动定位：恢复 target（无球回退全部）→ 读该 target 的位置键 →
  无记录则：全部/未归属 = 第一个未归属球（现状），按人 = 第一个球
- 改归照常 `touched[key] = true`（保护规则不动）
- 持久：target 写 review 键（空串=全部）

### 删簇（扩展现有 clState 键）

`scorer_<session>_clState` 新增第四个子键 `deleted`（平铺对象
`{ gid: true }` 墓碑；初始值/加载回退/保存的 stored 合并与
merges/clAssign/collapsed 三个子键同套路；saveClState 的 del 删除
清单**无需扩展**——墓碑只加不减，永远不会有待删键）：

- 入口：簇区每个显示组行的行尾加"删除"钮（所有组都有，展开/折叠
  行都显示；位置不依赖"拆开"钮——拆开钮仅多簇合并组未折叠时才有）；
  点了 `confirm("删除簇#N？组内 X 球的归属不变，
  可在第三步逐球核对")`，取消不动
- 确认后 `clState.deleted[String(g.gid)] = true` 并重渲染；
  渲染分组时跳过 `deleted[gid]` 的显示组（**在 merges 折叠成显示组
  之后过滤**——删的是显示组，与立哥肉眼所见的行一一对应）
- **不动** ITEMS / marks / touched / clAssign：簇只是分组预填视图，
  删簇≠删球≠清归属；组内球在逐球区照常出现，归属判错走第三步
- 逐球区进度行的 `簇#N` 标注（show() 里读 groupIdOf）**保留不动**
  ——它是逐球区信息，与簇区行是否可见无关
- 无页内撤销（YAGNI）：墓碑与 merges 一样随 localStorage 持久，
  重生成页面仍生效；误删找回 = 浏览器清站点数据后重开页面
  （使用手册认人节注明）

### 三步标题条

- 名单区上：`第一步：判队伍——拖队员到正确队伍行，点"改名"填真名`
- 簇区上：`第二步：并簇认人——同人的簇拖到一起，点队员名应用到整组；
  误分组的簇点"删除"移除（不动球和归属）`
  （无 --clusters 时整条随簇区隐藏）
- 核对区上：`第三步：逐球核对——选核对对象，判错直接点正确球员`
- 样式：一行小字灰黄标题（`.stepbar`），不挤压现有布局

## Boundaries

- Always：质量门全绿后提交；localStorage 读写容错；touched 优先不动
- Ask first：无（零新依赖、零新 CLI 参数、零 schema 变更）
- Never：不给改标签（tag）；不改 roster.json schema；不改既有
  marks/touched/clState/teamovr 键格式（clState 只**新增** deleted
  子键，既有三子键格式不动）；核对过滤不改 ITEMS 本体
  （只改渲染/导航的可见集）；删簇不动 marks/touched/ITEMS
