# review02：改标/补锚不再自动跳走（label-jump-goal 追加修复）

## 结论

**通过**。立哥生产反馈 1 例 UX 缺陷，定位为既有"自动前进"语义与补锚流程冲突；单行级修复 + 浏览器实测命中，844 passed。

## 问题实录（2026-08-27 立哥反馈）

批次已基本标完（仅剩末尾个别未标），立哥在第 2 个事件上按 J 补锚，页面直接跳到最后一个事件。

根因：`mark()` 的自动前进逻辑（首轮标注提速设计）无条件跳到"下一个未标注事件"——补锚场景下事件全是已标状态，按 J 后被拽到仅剩的未标事件（实录中即最后一个）。该语义对首轮标注正确、对 G+J 补锚流程是捣乱。

## 修复

`gen_label_page.py mark()`：**仅首次标注（isNew）自动前进；改标/补锚（事件已有标记）原地 `show(cur)` 刷新显示**，导航交给 G/翻页。首轮标注行为逐字不变。

## 实测账（2026-08-27，MCP 浏览器驱动生产页面）

| 场景 | 操作 | 结果 |
|---|---|---|
| 改标原地不动 | 预标 0..n-2（含事件 1 = 0249#e19），show(1) 后 markGoal | 停留 e19 ✓ |
| 首标自动前进 | 仅剩末尾未标，未标事件首标 | 前进到下一个未标 ✓（首轮语义不变） |
| 插曲 | 首验失败 | 系测试脚本误把事件 1 留成未标（isNew=true 正确前进）+ 浏览器缓存旧页面；ignoreCache 重载后复验通过——非代码问题 |

关口：ruff format/check 全绿；`pytest` **844 passed**（+1 断言 `if (!isNew)`/`show(cur;)`）。
