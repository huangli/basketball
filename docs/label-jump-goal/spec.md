# spec：标注页"跳到进球"导航（label-jump-goal）

## 背景与问题

goal-anchor 落地后，立哥补锚的工作流是"只过已标 J 的片段，在入网帧按 J 定锚"。但标注页现有导航只有"跳到未标"（jumpUnmarked）与逐条翻页——已全标完的批次（如 20260822_citymonkey batch1，351 事件）要补锚只能逐条翻或"跳到未标"空转，无法直达已标进球的事件。

## 目标

标注页加**"跳到进球"导航**：G 键 / 按钮，跳到下一个 `r === "goal"` 的已标事件（循环查找，优先当前位置之后；全批无 goal 标记时原地不动）。配合 goal-anchor：G 定位 → 循环播放入网帧按 J 补锚 → 再 G 下一个，已标 P/F 的事件完全不经过。

## 非目标（边界）

- 不改 mark/导出/分组任何现有逻辑；不加筛选视图/隐藏非进球事件（只加跳转，页面结构不动）
- "进球但不收"（P）不算跳转目标（补锚对象是 confirmed 进球）
- 不追溯修改已导出 goals.json

## 方案

1. `gen_label_page.py` 模板：加 `jumpGoal()`——`EVENTS.findIndex` 当前位之后首个 `marks[key].r === "goal"`，无则从头找（循环）；按钮 `跳到进球 (G)`（nav 样式，放"跳到未标"旁）；keydown 加 `g`；帮助文案补 G
2. 测试：断言按钮、`jumpGoal` 函数、G 键绑定与 goal 判定条件存在（JS 行为靠实测）
3. 手册快捷键表补 G 行

## 成功标准

- 351 事件全标批次实测：反复按 G 在全部 J 标事件间循环跳转，不经过 P/F 事件
- `ruff format && ruff check --fix && pytest` 全绿；手册同步
