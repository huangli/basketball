## 起因（验收反馈）

立哥实操 triage.html 扫尾：**全景 480px 缩略图根本看不出是否进球**。
实证：3840×2160 素材抽帧 1920×1080 缩到 480px 宽后，球仅几像素、
筐区占图 <2%，入网瞬间不可判读——墙的"只能否"功能失去意义。

## 修复内容（commit 见 todo 回填）

1. **筐区裁剪**：`gen_triage_page.py` 新增 `--hoops` 参数，读 detect_hoops
   产物建 事件 key → 锚点 (cx,cy) 映射（批次 3 实测 234/234 事件均有锚点）；
   以锚点为中心裁帧宽 40% 的 16:9 窗口、640px 落盘。锚点缺失事件降级全景
   480px 并记降级清单；不传 --hoops 整页全景（向后兼容）。
2. **布局**：卡片改"锚点帧（入网瞬间）100% 宽大图主判 + ±0.4s 两帧小图
   参考"，网格 minmax 660px。原 3 帧等宽横排在 500px 卡内每图仅 ~157px，
   裁剪图也会被缩回不可判读，布局必须跟着改。
3. **run_session.py** ⑦ 步 triage 命令补传 `--hoops`。

## spec-reviewer 复审结论（第 5 轮，通过无阻断）

四条可选改进已全部顺手修复：

1. **主图取帧假设消除**：钳位去重/缺帧时锚点项不一定是 thumbs 中间项，
   改 thumbs 显式带 `is_anchor` 标记、页面按标记取主图（无标记回退中间项）
2. **NaN/inf 锚点防御**：load_anchors 加 `math.isfinite` 过滤（Python json
   默认放行 NaN 字面量，round(nan) 会炸整页生成）
3. **docstring 口径修正**：裁剪窗比例固定恒在帧内，4:3 帧裁横向带（不存在
   "帧图比裁剪窗窄"场景）
4. **全景降级角标**：`mode==="full"` 的卡片显示"全景降级"标记，立哥可一眼
   识别非筐区特写的卡片

修复后 pytest 466 passed、ruff 全绿、批次 3 重生成 234/234 零降级、
页面 node --check 通过。
