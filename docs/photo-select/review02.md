# review02: photo-select 第二轮调参（冲击力导向）

日期：2026-08-15 审查人：实施 agent 自审（实测后定稿）

## 背景

立哥第一轮实看反馈：候选图冲击力不够，要**力量感 / 特写 / 进球最后一瞬 / 篮板**。
任务书 = `spec.md` §方案 1 的「第二轮调参」节，本轮严格照做。

## 调参内容（对应 spec 逐条）

1. **新增球筐距信号（主信号，权重 0.35）**：`load_hoop_events` 读场次目录全部
   `hoops_batchN.json`，归一为 fid（去后缀）→ 事件清单（window 片内秒 + anchor 筐心，
   检测尺度，与 mot_cache 球心同尺度直接算距离）。窗口内信号 = max(0, 1 − 距离/400px)，
   多窗口覆盖取最高；窗口外 / 无 hoops 文件记 0 不报错；schema 损坏抛 SchemaError。
2. **进球锚点加成**：`load_goal_anchors` 读 `goals_batchN.json` 只取 confirmed；
   `apply_goal_boost` 对 anchor_time ±0.6s（含端点，浮点容差 1e-6）内帧分数 ×1.5，
   且每球窗口内最高分帧标 `force_pick`，在 10s 分桶保底之外额外保底入选。
   （spec 口径「进球瞬间必进候选」实现为**每球保底 1 帧**：窗口内全部 ±3 采样帧保底会
   让 122 球贡献 ~700+ 帧淹没时间覆盖，与 spec「约 200 张、时间分桶保底」冲突。）
3. **权重重排**：球筐距 0.35 / 主体尺度 0.20 / 球速 0.20 / 人球交互 0.15 / 球高 0.10
   （原：球速 0.35 / 交互 0.25 / 尺度 0.25 / 球高 0.15）。
4. **特写构图**：裁框高 = 主体（人+球联合框）高 / 0.65（目标占裁框高 55~75%），
   头顶留白 10%→5%，竖向只锚定头顶、不再为主体底部外扩/重夹（允许切脚/切膝）；
   主体占比 >85% 视为过近 penalized（与 upscale>1.5 并列，惩罚系数 0.5 不变）。
   注：人框都在画面内且裁框竖向锚定头顶时，主体占比 65% 意味着脚部通常仍在框内；
   「允许切脚」实际生效于收缩路径与宽度约束主导的场景。
5. **`--force`**：`reset_candidate_outputs` 清空 `candidates/` 与 `photo_candidates.json`
   全量重跑；不带 --force 时旧版本（v1）candidates 视为不兼容自动全量重算（不再崩）。
   `CANDIDATES_VERSION` 升 2，候选条目新增 `goal_boost` 字段。

## 测试（先行，共 18 项新增/修订）

- 球筐距：筐近 > 筐远；无 hoops 不报错且同分；窗口外记 0；多窗口取最近筐
- 进球加成：窗口内 ×1.5、窗口外不变、±0.6s 边界含端点（9.4/10.6 加成，9.2/10.8 不加）、
  每球只保底最高分 1 帧、空锚点/无帧锚点原样返回
- 分桶：force_pick 额外保底且不参与桶内保底/补齐（不重复入选）
- 特写构图：占比落 55~75%、留白 ≥5%、贴底边头在框内、巨人近景 >85% 降分
- 加载器：多批次合并、缺失记空、schema 损坏抛 SchemaError；--force 清空幂等
- 关口：`ruff format` + `ruff check --fix` 全过，`pytest -q` 全绿（619 测试）

## 遗留

- **进球帧构图未围绕球/筐**（本轮实测最大不足）：force_pick 帧构图仍锚定最大人框，
  进球瞬间球在筐上、距任何人 >0.75×人高 → 联合框不含球，构图偏宽、前景路人可抢镜
  （抽查 c004/c079/c132/c185）。下一轮建议：goal_boost 帧构图锚定「球+筐心」再联合最近人。
- **进球瞬间与清晰度门槛张力**：3 球（0195@15.1s、0273@5.7s、0242@12.9s）的保底帧
  ±3 防抖组全帧 Laplacian 方差 <15 整组丢弃——高速运动帧天然模糊。可考虑：
  force_pick 组放宽门槛（如 ≥8 取最清晰帧）或扩大防抖半径至 ±5。
- spec「±0.6s 内帧额外保底入选」字面口径（窗口内全部帧保底）与「约 200 张 + 时间覆盖」
  冲突，本轮按每球保底 1 帧实现；若立哥要每球多张连拍式候选，需另开口径。
- `video.py photo` 子命令未加 `--force` 透传（本轮直接跑 rank_photos.py）；旧 v1 候选
  在 `video photo` 下会触发版本不兼容自动全量重算，行为正确但不清 candidates 目录
  残余旧图（JSON 不引用，不影响页面）。
- 篮板争夺专用信号（多人框聚集筐下 + 球在筐上方）spec 明确暂不做，先看球筐距效果。
- 筐事件窗口口径偏宽（R1 候选 85.3% 都在某窗口内），筐距信号区分度主要来自
  「距筐心距离」而非「是否在窗口内」。
- 候选超发至 334 张（122 进球保底 + ~221 分桶保底 > 目标 200），符合「宁多勿漏」，
  但页面点选工作量上升；若立哥嫌多，可考虑保底帧不参与补齐以外的增发。
