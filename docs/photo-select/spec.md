# spec: 场次精彩照片自动挑选（photo-select）

日期：2026-08-15 状态：定稿（spec-reviewer 两轮通过）

## 目标

每个场次自动生成约 200 张「精彩、有冲击力」的高清照片候选（自动构图裁切放大），
瀑布流页面展示，立哥人工点选确认，确认的照片导出留用。

## 需求口径（立哥 2026-08-15 定）

- 不需要判断进球者/队友，不做认人；只要画面精彩、有冲击力
- 每场约 200 张候选，宁多勿漏，最终人工挑选
- 自动裁切放大：以最具冲击力的主体构图，不是整帧缩略图
- 瀑布流页面点选，确认的留下（导出到成品目录）
- 架构定位不变：机器排序 + 人裁判

## 边界

- 不做：认人、聚类、按球员/队伍归类、封面文字合成（后续另议）
- 不新增重型模型：打分只用现有 mot_cache 检测 + OpenCV/NumPy；CLIP 初版不上（候选量 200 不需要精排，留给人工）
- 不改动检测流水线既有产物；mot_cache 只读，读取走 `crop_scorers.load_mot_cache`（带 schema 校验的唯一入口）
- 素材缺失/无缓存的文件：跳过并记日志，不中断（AGENTS.md 素材流动原则）
- **比例策略**：构图比例跟随素材（AGENTS.md「输出比例跟随素材」）——16:9 场次裁 16:9 出 1920×1080；4:3 场次裁 4:3 出 1440×1080（老 4:3 场次缓存坐标系为 1920×1440，宽高同因子换算仍成立）。同场次混入多比例素材时按比例分桶各自处理

## 数据源（已验证 2026-08-15）

- `work/detect/<视频名>_mot_cache.json`：`{"frames": N, "balls": [[{conf,box,cx,cy,sec,frame_idx}...]...], "persons": [[[x1,y1,x2,y2]...]...]}`，5fps 采样，坐标为检测尺度（1920 宽，需乘 session_facts 宽度/1920 换算回原图，实现时先断言验证比例）
- `work/<场次>/session_facts.json`：每文件 width/height/fps/duration
- `work/<场次>/hoops_batchN.json`（第二轮新增）：events 每项含 fid/window/anchor（筐心，检测尺度），给球筐距信号
- `work/<场次>/goals_batchN.json`（第二轮新增）：confirmed 球的 file + anchor_time，给进球瞬间加成
- 原视频：按 `video_cli.json` 记录的 srcdir 定位

## 方案

### 1. 候选帧打分（rank_photos.py）

对每个 mot_cache 的每个采样帧计算冲击分，信号全部来自缓存（每帧只取 max conf 球，conf < 0.35 视为无球）：

- 球速：相邻帧球心位移（快 = 攻防激烈）
- 人球交互：最近人框与球心距离（持球/出手瞬间分高）
- 主体尺度：最大人框面积（人越大越近越有冲击力）
- 球的高度：球 cy 越小（越靠画面上部=出手/空中）加分

**第二轮调参（2026-08-15 立哥反馈：要冲击力——力量感/特写/进球最后一瞬/篮板）**：

- **新增球筐距信号（主信号）**：读 `work/<场次>/hoops_batchN.json` 的 events（fid + window + anchor 筐心，检测尺度），
  球到筐心距离越近分越高（覆盖进球瞬间、篮板、封盖——都发生在筐附近）；hoops 缺失的文件该信号记 0 不报错
- **进球锚点加成**：读 `goals_batchN.json` 的 confirmed 球，anchor_time ±0.6s 内帧分数 ×1.5 加成，且**每球保底窗口内最高分 1 帧**入选（R2 实测定稿口径；字面全帧保底会超发 700+ 帧冲垮时间覆盖，见 review02）
- **权重重排**：球筐距 0.35 为主，球速降到 0.20、人球交互 0.15、主体尺度 0.20（上调，特写导向）、球高 0.10
- **特写构图**：裁切收紧——主体（人+球联合框）目标占画面高度 55~75%（原保守外扩作废），允许切脚/切膝，
  头顶留白 ≥5% 即可；主体超高占比（>85%）才视为过近降分
- 篮板争夺信号（多人框聚集筐下 + 球在筐上方）暂不做，先看球筐距效果
- 重跑需全量重出（裁切参数变了）：rank_photos 加 `--force` 清 candidates 重跑；旧候选页作废

时间分桶（10s/桶）先每桶保底 1 张，再按分数全局补齐至 200，保证时间覆盖不堆在少数回合。

### 2. 帧提取与防抖（rank_photos.py 内）

- 候选时刻 ±3 原帧（59.94fps 下 ±~50ms，仍远小于 5fps 采样间隔 200ms，不会换回合）各抽 1 帧，共 7 帧，全分辨率
- 候选裁切区域算 Laplacian 方差，取最清晰的一帧（5fps 采样点常落在运动模糊帧上）
- ffmpeg 精确 seek（`-ss` 前置 + `-frames:v 1`）出 jpg

### 3. 自动构图裁切

- 主体 = 最大人框（若球在附近则联合包围盒包住人+球）
- 外扩到素材比例（16:9 或 4:3）；头顶留白 ≥10%（R2 起特写构图改为 ≥5%，见 §方案 1 第二轮调参）；人置于三分法构图线附近；裁框夹回画面内
- 16:9：裁切宽 ≥1920 → 出 1920×1080；4:3：裁切宽 ≥1440 → 出 1440×1080；不足则等比放大（>1.5 倍降排序分并记日志）
- 输出 JPEG q95，`work/<场次>/photos/candidates/`

### 4. 瀑布流确认页（gen_photo_page.py）

- 静态 HTML，CSS columns 瀑布流，单击点选/取消，双击放大查看原图
- 点选/再点取消；快捷键：数字键翻页、A 全选本页、Enter 导出（沿用 label 页交互风格）
- 导出：生成 selections JSON 下载 + 页面内说明保存路径；落盘后由 `rank_photos.py --apply` 把确认照片复制到 `output/<场次>/照片精选/`；**selections.json 读入即做 schema 校验**（防存错文件/半截下载，rules.md §0.2）
- 每张卡片标注：视频序号、时刻、排序分（辅助判断，可隐藏）

### 5. 产物

- `work/<场次>/photos/candidates/*.jpg`（200 张候选，含裁切后全尺寸）
- `work/<场次>/photos/photo_candidates.json`（每张：源视频、时刻、裁框、分数、状态）
- `work/<场次>/photos/photo_page.html`
- `output/<场次>/照片精选/*.jpg`（立哥确认后）

## 成功标准

- 单场（~148 文件）候选生成 ≤30 分钟（检测零重跑，仅 ffmpeg 抽帧）
- 200 张候选时间分布覆盖全场（任 10 分钟区间 ≥5 张）
- 确认导出链路端到端可跑：页面点选 → JSON → 照片精选目录
- ruff format/check + pytest 全绿；新增逻辑有测试（打分、构图、分桶）

## 风险与对策

- 检测尺度换算错误 → 可执行断言：换算后所有框必须落在 `[0,width]×[0,height]` 内（容差 1%），且缓存坐标 max x ≤ 1920+ε、max y ≤ 检测帧高+ε（检测帧高 = facts.height/(facts.width/1920)，16:9→1080、4:3→1440），违反即抛 SchemaError 停跑
- 缓存每帧多球候选且含低置信度假球（0.18~0.34）→ 每帧只取 max conf 球，且 conf < 0.35 视为无球
- 高速运动帧全模糊 → ±3 帧选清晰仍失败时整组丢弃并记日志
- 无球/无人帧混入 → 打分为 0 自然沉底，不硬过滤（规则留口）
