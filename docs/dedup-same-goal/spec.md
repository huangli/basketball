# spec：标注页同球双 J 自动识别（dedup-same-goal）

## 背景与问题

人工标注环节的系统性重复源：同一回合的"持球时刻候选"与"入网时刻候选"被事件合并拆成两个事件，两个事件的审核片段都包含同一入网画面，立哥对两个都按 J，产生同球双 J。

实测账目：

- **批次 3**：立哥标 61 J，其中 10 条为同球重复（16%），需逐帧鉴定去重（约 1 小时机器+人工复核）
  - 同文件 8 组（anchor 差 2.3~4.2s）：200730@3.0/6.1、200854@3.5/5.8、201604@6.2/8.6、201718@2.7/5.7、203946@1.7/5.9、204746@4.2/7.9、205942@11.5/14.9、210152@17.3/20.4
  - 跨文件三标 1 组：203618@9.9 + 203628@3.5（去重鉴定时帧级修锚点为 2.2）+ 203638@1.3 同球
- **批次 2**：195912 同例（37 标 → 35 球）

## 目标

标注环节**源头消重**：标注页自动识别"疑似同回合"的事件并分组提示，让立哥标注时即知"这可能与同组其他事件是同一球"，不再双标。

## 非目标（边界）

- **不改事件合并算法**、不动检测/候选/筐轨迹任何上游环节
- **不做自动删除/自动合并**：机器只提示，判定权在人（防误并真两球）
- **跨文件同球识别不在一期**：文件名时间戳不完全可信（205204/205158 名义重叠 3.2s 实为不同回合；203918/203928 相邻文件不同半场），跨文件误判代价高，二期再议
- 不追溯修改批次 1/2/3 已封存的 goals（已人工去重完毕）

## 关键约束（反例必须保住）

以下真两球不得被规则误判为"同球"（一期用"仅同文件分组"天然规避，二期若做跨文件必须回归这两条）：

- 203918@7.5 / 203928@3.9：相邻文件、不同半场两个球
- 205204@1.1 / 205158@10.4：文件名时间戳重叠、不同回合两个球

## 方案

1. **分组规则（一期，仅同文件）**：同一 fid 内，两事件的审核窗口重叠即视为疑似同回合。审核窗口 = [anchor − 前窗, anchor + 后窗]，前窗/后窗取审核片段实际口径——批次 2/3 为**前 2s / 后 4s**（`gen_review_clips.py` 的 `CLIP_BEFORE_SEC = 2.0` / `CLIP_AFTER_SEC = 4.0`，实现时从该模块读常量不硬编码；注意 `gen_label_page.py` 有同名不同值常量，那是导出 goals 的剪辑窗口前 4 后 2，**勿混**）。批次 3 的 8 组同球对 anchor 差 2.3~4.2s ≤ 2+4=6s，窗口必然重叠，全部命中。
2. **标注页呈现**（`gen_label_page.py`）：同组事件加同色标识（组号→颜色轮换，呈现落点以页面结构为准，现为单事件翻页器的有色文字标签）+ 文字标签"疑似同回合（组 N，共 M 个）"；标注第二个时视觉上即可识别。
3. **导出校验**：导出 goals.json 时若同组存在 ≥2 个 J，弹确认框列出该组（"组 N 有 2 个进球标记，是同一球还是两个球？"），立哥确认后才允许导出；确认"两个球"则正常导出（保留真两球通道）。

## 成功标准

- 批次 3 回放验证：`work/20260722/review_batch3/events_index.json` + 原始导出 `20260722地平线/goals_20260722_3.json`（61 J）跑分组规则，8 组同球对全部命中分组、0 误分组。**"0 误分组"口径 = 任意两个不同球的 confirmed J 不被并入同组**（等价：同组 ≥2 个 confirmed J ⇒ 二者为同一球；8 组同球对属正确命中，由前条保证）。2026-08-09 实测修订：42 个同文件独立球中 9 个与非 J 邻事件同组——每组恰 1 J，帧图抽查 203544@9.6 / 203006@17.1 均为另一次投篮画面、与组内 J 非同一球，属正确提示行为；"独立球不入任何组"的严格口径会误伤该提示功能（且会倒逼收紧窗口，危及 8 组同球对召回：anchor 差上限 4.2s，对 6s 窗口余量仅 1.8s）
- 下一生产批次：同球双 J ≤1 例（当前 16%）
- `ruff format && ruff check && pytest` 全绿；新增分组逻辑单测
