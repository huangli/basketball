# 进球检测方案（当前版，2026-07-26）

> 取代 `docs/superpowers/specs/2026-07-23-yolo-ball-trajectory-detection.md`（v4 设计稿，检测细节已演进）。
> 本文档反映**已实测验证**的实现，数据全部来自试点实测。

## 1. 目标

从原始视频（DJI 素材）中找出全部进球（球入网），输出 `goals.json`，
再按规格（前 4 秒 + 后 2 秒、1080p 比例跟随素材：16:9 出 1920×1080 / 4:3 出 1440×1080、50fps、H.264+AAC、100fps 素材入网后 2 秒半速）
合成 队伍/个人 进球集锦。约束：不花钱（本地优先）、人工审核 ≤10 分钟/场（目标）、
召回优先（宁多报不漏报）。

## 2. 端到端流水线

```
原片
 ① 抽帧      5fps，降采样到 1920 宽（本地 ffmpeg）
 ② 球检测    abdullahtarek YOLO（球）+ yolov8n（人，持球排除用）（本地 CPU）
 ③ 运动学候选 MOT 最近邻连成轨迹，两条进球签名：
              a) 静止段：连续 ≥4 帧位移 <40px（球停在网里）
              b) 断轨重连：球消失 0.6–1.4s 后在 ≤400px 内重现且 0.8s 内有后继
                 （入网遮挡签名；a 有前驱、b 端 conf≥0.3、盲区无检测）
              过滤：死球(停>3s)、持球(球框覆盖率>0.5落入人框；
                 原 IoU>0.3 经 7886 检测实证数学上不可触发，2026-07-26 审查修正)
 ④ 精筛（双轨，按 token 预算切换）
              A 纯人工：直接进 ⑤
              B VLM：Kimi K3 双尺度(420/630)各判 1 次"球进没进"，任一 YES 保留
 ⑤ 事件审核视频 相邻候选(≤2s)合并为事件，每事件一段放大视频，
              2 倍速、带编号水印；立哥看视频标进球编号
 ⑥ goals.json → 合成  build_highlight.py 按规格切片、concat
```

脚本与产物对应：`test_abdullahtarek_mot.py`(②③) → `pilot_candidates.py`(候选清单) →
`test_vlm_filter.py`(④B) → `gen_review_clips.py`(⑤) → 人工标注 →
`build_highlight.py`(⑥)。模型在 `models/`，缓存在 `work/detect/`。

## 3. 关键设计决策（都是实测换来的）

1. **不检测篮筐，只检测球**：筐标定三次翻车（v2/v3），废弃；且筐+网在检测器眼里
   本身就是"常驻球形物"，按位置过滤背景必然误杀进球（热点过滤已证伪）。
2. **断轨重连是召回关键**：入网遮挡 + 相机平移造成 0.8–1.6s 检测盲区，换模型/调参
   都突破不了 50% 召回；把"消失→重现"变成判据后，两个漏检文件全部找回。
3. **球检测用 abdullahtarek**：三模型头对头实测最好（假阳性 2.5/帧、GT 帧 conf 0.73–0.89）；
   Lumos-88 假阳性爆炸（10–14/帧），446f6e6e79 不可用（conf 0.01–0.4、框跨半屏）。
4. **FP 只能靠语义**：残余假阳性是海报印刷球/球员腰带膝盖/活球动作（conf 可达 0.8+），
   运动学规则无法区分，必须语义判断（人或 VLM）。
5. **VLM 双尺度任一 YES**：K3 单次判定会摇摆（同图 YES/NO 都出过），
   420/630 两尺度各判一次、任一 YES 即保留（召回优先）；图必须 840px 边长
   （448px 时球仅 ~8px 会漏看）、紧凑 3 帧（t0±1s；5 帧会稀释）。
6. **审核视频 2 倍速**：立哥实测可稳判；声音保留（欢呼是天然进球信号）。

| 事件合并 | 413 候选 → 87 事件（0.16 事件/秒）；审核视频 1x ≈ 素材 1.09 倍长，2x 观看耗时 ≈ 素材时长 ×0.54 |

## 5. 已证伪（勿再尝试）

- 筐 ROI 标定（v3，烧 ¥100+）、LRF 低清检测（球 3–5px）、音频检测、像素/运动量法
- Lumos-88（224 张训练图、无人机视角不匹配）、446f6e6e79_yolo11m
- 背景热点位置过滤（筐是常驻检出物，误杀进球）
- 4 球样本训练 sigLIP+logistic（留一文件 CV 不泛化，需 20+ 进球样本）
- zero-shot CLIP（正样本一半进不了 Top25）
- VLM 448px 小图 / 5 帧稀释 / 严 YES-NO 无分析提示（都会全判 NO）
- K2.6 替代 K3 做精筛（2026-07-27 验证集实测：进球级 2/4 vs K3 3/4，
  负样本留存 29/80 vs 8/80，召回与精度双输；reasoning 输出 token 也更高，
  ~6.7K/候选 vs K3 ~4K/候选；缓存 `work/label/vlm_cache_k26.json`）

## 7. 生产计划（双轨）

- **人工轨**（零 token）：检测(后台) → 事件审核视频(2x) → 立哥分批标 → goals.json → 合成
- **VLM 轨**（额度够时）：候选先过 K3 双尺度精筛（审核量 ÷6.4）→ 剩余事件人工确认
- 照片库认人（待立哥供照）：每人 1–2 张清晰照片，sigLIP 人像比对自动标进球者；
  认不出进"未识别"桶人工兜底

## 8. 风险与待办

- 候选窗口覆盖率 ~95%，剩余 5% 未覆盖时段的漏检无法从审核视频发现
  （如需全召回证明，补"全段概览"低清视频）
- VLM token 消耗大（全量一场 ≈ 34M 输入/19M 输出），受订阅额度约束；
  K2.6 降级已证伪（见 §5），K2.5 未实测、默认不抱期望；
  省成本方向只剩外部 qwen-vl（~¥10/场）
- 成片混入 DJI data 流（不影响播放，concat 步改默认流选择可去）
- 锚点精修：试点为人工 ±1s 映射 + 帧级复核；全量需半自动精修到 ±0.1s
