## 1. 检测流水线

- **断轨重连是召回的唯一关键判据**
  入网遮挡 + 相机平移造成 0.8–1.6s 检测盲区，换模型/调参都突破不了 50% 召回；把"球消失 0.6–1.4s 后在 ≤400px 内重现"作为签名后漏检全部找回（试点 4/4，批次 1 rejoin 型占 91%）。
  出处：主文档 §3.2、需求文档 §5.1
- **球检测主力模型 = abdullahtarek_ball.pt，勿换**
  三模型头对头实测：假阳性 2.5/帧、GT 帧 conf 0.73–0.89；Lumos-88 假阳性爆炸（10–14/帧），446f6e6e79_yolo11m 完全不可用（conf 0.01–0.4、框跨半屏）。
  出处：主文档 §3.3
- **残余假阳性只能靠语义（人），运动学规则到头了**
  海报印刷球、腰带膝盖、活球动作 conf 可达 0.8+，任何轨迹/位置规则都区分不了。
  出处：主文档 §3.4
- **筐不做检测目标，只做取景/排序输入**
  筐 ROI 标定三次翻车（烧 ¥100+）；筐+网是常驻球形检出物，按位置过滤候选必然误杀进球（热点过滤已证伪）；detect_hoops.py 仅服务审核裁剪与筐距排序。
  出处：主文档 §3.1、§5
- **筐距排序有效但只能排序不能裁剪**
  真进球筐距 66/260/570px vs 全体候选中位 540px；弹出滚远型（570px）会沉底，按筐距裁剪会漏球。
  出处：需求文档 §5.1.4
- **轨迹物理特征判进球已证伪全链**
  91% 候选锚点恰在检测盲区中点（入网瞬间本来就没轨迹），5fps 下入网仅 1–2 采样点；"下落加速→骤停"签名 7 真球命中 0。
  出处：主文档 §5、需求文档 §5.2
- **持球过滤用框覆盖率 >0.5，不是 IoU>0.3**
  7886 条检测实证 IoU 判据数学上不可触发（2026-07-26 审查修正）。
  出处：主文档 §2③
- **时空双条件事件聚类消同球重复**
  纯时间 2.0s 聚类把同球拆两事件（190354@16.5/19.1，2.6s/309px）；改 gap≤2s 或 gap≤6s 且 dist≤400px 后 113→84 事件，400px = 实测 308.6px +23% 余量。
  出处：docs/batch2/spec.md、主文档 §7
- **长事件锚点取末成员，不取 max-conf**
  批次 1 实证 3 例（0544/1508/1948）max-conf 锚点切错时段，真进球在事件尾部；末成员锚点全部修对。
  出处：docs/batch2/spec.md、主文档 §7⑤
- **审核片段要带结局尾巴**
  入网后窗口后 2s 改后 4s + 默认全景 + 跨文件续接（批次 1 验收纠错落地），批次 2/3 未再出现弹出误判与结局缺失类问题（批次 3 仍有 1 例人工帧鉴定修锚点）。
  出处：主文档 §4 批次 2
- **候选级自动剔除若启用，必须配套"未覆盖时刻补标"**
  批次 1 验证：39 个 VLM NO → 20 未覆盖时刻 → 补标 16 事件人工复核 0 进球，账目才闭环。
  出处：主文档 §4 批次 1、§7④

## 2. 机器裁判已证伪（勿再尝试）

- **总结论：架构 = 机器排序 + 人裁判**
  盲区事件入网瞬间像素证据弱是所有模型的共同天花板；任何把真进球从人工视野移除的步骤都撞这条墙。
  出处：主文档 §5、AGENTS.md 工作流约定
- **K3 事件级判定已下线（2026-08-01 立哥定）**
  批次 2 对照账：YES 7 次仅 6 真 1 误、只覆盖 6/35 真球（捞不动）；NO 36 次误杀真球 4 起（排尾险致漏球）；667K 输入 token 换不来排序性价比。
  出处：主文档 §4 批次 2
- **K3 诚实模式下 YES≈0、NO 精度 ~95%，两端都不够自动权**
  99% 召回红线下判定只配做排序信号；批次 1：365 候选中 325 UNCLEAR / 39 NO / 1 YES。
  出处：主文档 §3.5、需求文档 §5.3
- **豆包视频模型慢放判定同样证伪**
  doubao-seed-2-0-pro 0.2x 慢放：真球 8 球 YES 2 / UNCLEAR 1 / NO 5（真值修正后）；~15K token/段只够小批量疑难复核。
  出处：主文档 §4 批次 1 P1
- **zero-shot CLIP 证伪**
  正样本一半进不了 Top25。
  出处：主文档 §5
- **4 球样本训 sigLIP+logistic 不泛化**
  留一文件交叉验证失败，估计需 20+ 进球样本才谈得上训练。
  出处：主文档 §5
- **K2.6 替代 K3 双输**
  进球级 2/4 vs 3/4，负样本留存 29/80 vs 8/80，reasoning token 还更高（~6.7K vs ~4K/候选）。
  出处：主文档 §5
- **裸 YES/NO 一律不可信**
  无推理文本的判定（批次 1 实测 63/113，其中 61 NO + 2 YES）全部降级 UNCLEAR——`normalize_verdict` + `demote_fallback_no` 是硬规则，勿绕过。
  出处：主文档 §3.5/§5
- **VLM 图片规格红线**
  必须 840px 边长（448px 时球仅 ~8px 会漏看）、紧凑帧（5 帧稀释会全判 NO）、禁止"严 YES-NO 无分析"提示词（同样全判 NO）。
  出处：需求文档 §5.1.3/§5.2
- **其他已证伪小项**
  LRF 低清检测（球 3–5px）、音频检测、像素/运动量法、筐 ROI 标定、背景热点过滤。
  出处：主文档 §5
- **统计纪律：0 漏检宣称需 299 独立正样本**
  rule of three ≈15 个场次，此前自动剔除长期关闭，NO 只排序；每批抽样审计 NO 区。
  出处：主文档 §7

## 3. 认人流程

- **投篮者定位用轨迹法，逐帧散点规则全部证伪**
  mot_cache 的 persons 无 track ID、逐帧 max-conf 球位会瞬移（0.2s 跳 800px）；v2 的 IoU 链投票法 17 球明确错 2。v3 轨迹法（窗口内重链 min_length=1 → 末端贴候选锚点 → 回放找最后持球人框）实测 OK 17/17、SKIP 0。
  出处：docs/scorer/spec.md B2
- **裁图/预填只是辅助，视频是终裁**
  残余风险（锚点落防守人、附近只有场边人）轨迹法无解，靠确认页预览片段人工兜底——所有机器预填都不得当终裁。
  出处：docs/scorer/spec.md、docs/scorer-cluster/spec.md
- **轨迹链会漂到场边广告静物（2026-08-15 车百鼎场次实测）**
  3 个球的投篮者裁图全部是同一块酒瓶广告牌（车百鼎=酒类赞助，场边环屏全是
  酒瓶广告）：人出画后 IoU 链延伸到静物区域，串人守卫只防跨队混裁、防不住
  "根本不是人"。三球聚类恰好成一簇（酒瓶簇），归属靠视频人工判。后续方向：
  crop_scorers 加"贴边+静止"停链守卫，或认人页加"裁图无效"标记把此类球挡在
  簇区外（只进逐球区视频认人）。
  出处：20260805_车百鼎 scorers_b1 簇6（0038 t20.6 / 0019 t13.4 / 0025 t12.4）
- **聚类定稿 = CLIP `--linkage complete --threshold 0.15`**
  实测 52 簇/62.6% 纯度（104 球 99 键入统）；85% 纯度需 81 簇无批量意义，按降级出口"纯度转观察值、簇级功能照上"。
  出处：docs/scorer-reid/review01.md 附 Phase B3
- **OSNet（Market1501）不比 CLIP 强，域差距吃掉专用模型优势**
  街景监控域 vs 俯视远景运动模糊球馆画面，各档位标定基本持平甚至略差（complete@0.15：43 簇/51.5% vs CLIP 52 簇/62.6%）；后端保留不推荐默认。
  出处：docs/scorer-reid/review01.md 附 Phase B3
- **全身外观路线在本素材已到天花板**
  下一步值得试的是照片库人脸 embedding（待立哥供照）——人脸是跨场景最稳特征。
  出处：docs/scorer-reid/review01.md 附
- **多裁选帧：质量分 = 归一化框面积 × Laplacian 方差**
  链上 IoU≥0.3、帧间隔 ≥0.5s 去重（连续帧裁剪无信息增量）、选帧窗口前后各 ≤2s。
  出处：docs/scorer-cluster/spec.md
- **读号用多帧众数投票，None 票不参与计数**
  同号 ≥2 张采纳；单票 high 采纳 low 归 None；多票全不同取唯一 high。旧数据重跑用跳票模式（--numbers-cache-only）零新调用回填。
  出处：docs/scorer-reid/spec.md、review01 阻断 1/2
- **K3 读号忠实度实测 5/5 无幻觉**
  但球衣互换时预填会错——确认页裁图必须在眼前，预填永远可一键改。
  出处：docs/scorer/spec.md Open Questions 2
- **颜色分队采样躯干中带（水平 60% × 垂直 25–60%）+ HSV 双阈**
  阈值按 17 张实裁图标定，近阈一律归"便服"。
  出处：docs/scorer/spec.md M4
- **缓存键用裁图 md5 不用 goal key；跨后端缓存必须全量保留**
  曾因按当前模型前缀过滤回写，OSNet 首跑把 CLIP 176 条 embedding 静默冲掉（阻断级 bug，已修并补回归测试）。
  出处：docs/scorer-reid/spec.md、review01 附

## 4. 标注与审核提效

- **审核视频 2 倍速可稳判，声音保留**
  欢呼是天然进球信号；审核片段本身烘焙 2x，页面默认保持 1x（有效 2x）——页面再叠 2x = 有效 4x 过快，S 键才切。
  出处：主文档 §3.6、docs/label-speedup/spec.md F2
- **同回合双事件→双 J 是标注侧系统性重复源**
  持球候选与入网候选拆两事件、两片段含同一入网：批次 3 实测 61 J 中 10 条同球重复（16%），机器+人工复核去重花了约 1 小时。
  出处：docs/dedup-same-goal/spec.md、主文档 §4 批次 3
- **分组规则 = 同文件内审核窗口重叠即疑似同回合**
  窗口前 2s 后 4s（从 gen_review_clips 常量读，不硬编码）；批次 3 的 8 组同球对 anchor 差 2.3–4.2s 全部命中、0 误分组。
  出处：docs/dedup-same-goal/spec.md
- **跨文件同球识别不做（一期）**
  文件名时间戳不可信、误判代价高；两组真两球反例必须保住（203918/203928 不同半场、205204/205158 文件名重叠实为不同回合）。
  出处：docs/dedup-same-goal/spec.md
- **机器只提示不自动合并/删除**
  同组标色 + 导出时同组多 J 弹确认兜底；真两球通道必须保留，判定权永远在人。
  出处：docs/dedup-same-goal/spec.md、docs/label-speedup/spec.md
- **"看一判全"只覆盖未标注成员、仅新标 J 时触发**
  已标事件（无论 J/P/F）一律不动——防止误改已判事件；误标可改判，localStorage 记录无数据损失。
  出处：docs/label-speedup/spec.md F1
- **新标注功能上线前用历史真值回放验证**
  批次 3 模拟"遇组内 J 即确认跳过"：自动跳过 ≥8 事件且 51 球每球仍至少一条 goal 被捕获——回放断言比人工抽查便宜且可复算。
  出处：docs/label-speedup/spec.md 成功标准 1
- **缩略图墙已下线：与标注页功能重复，三轮迭代救不回**
  全景缩略图球仅几像素 → 筐区裁剪仍判不了"进网还是弹出" → 悬停视频墙又与标注页重叠；"只能否不能是"的安全设计同时封死了墙的价值上限（能否的场景标注页一样快）。2026-08-11 立哥拍板下线，脚本已删（git 留档 cc4195e 前）。
  出处：docs/batch-speedup/review05-07
- **新交互页面先出最小可用版给用户试手感，再迭代**
  triage 墙三轮返工（全景→裁剪→视频）都在补"判读可行性"，而根因是墙与标注页的分工本身不成立；第一版就该先对比"墙否 vs 标注页直接否"的总耗时。
  出处：docs/batch-speedup/review07 §教训
- **人工标注基线：113 事件 ≈15–20 分钟**
  label.html 按键标注单事件 1–2 秒可判；瓶颈是量级叠加不是单条耗时，提效方向是减少看片条数。
  出处：需求文档 §4

## 5. 素材特性坑

- **大疆文件带 data 流 + 缩略图流，转码必须显式选流**
  `-map 0:v:0 -map 0:a:0`；否则成片混入 data 流（不影响播放但不干净）。
  出处：主文档 §8、需求文档 §2
- **文件名时间戳不完全可信**
  205204/205158 名义重叠 3.2s 实为不同回合；跨文件分析一律以画面内容为准。
  出处：主文档 §4 批次 3 系统性发现③
- **进球即停录导致片段尾截短是素材特性不是 bug**
  批次 3 的 51 球中 37 球入网后录像不足 2s（最短 0.8s）；切片/缩略图取帧都要容忍"物理不存在的帧"并记 WARNING 降级。
  出处：主文档 §4 批次 3、docs/batch-speedup/spec.md
- **处理前必须 ffprobe 确认尺寸/位深/帧率**
  20260722 素材是 HEVC 3840×2160 10-bit 59.94fps，与旧测试素材（4:3 8-bit 50/100fps）完全不同；尺寸参数按场次注入，宁可逐文件探测也不假设。
  出处：主文档 §6、rules.md §0.1
- **球在 1920 宽抽帧帧上仅 ~15–40px，入网瞬间常被遮挡**
  这决定了一切"看清入网"的方案都必须放大裁剪，也决定了机器裁判的像素证据天花板。
  出处：需求文档 §2
- **素材是流动的，不硬编码文件清单**
  每会话先重扫素材目录，goals/roster 以文件名为主键并容忍缺失；口径：自然删减可跳过，数据损坏必须停。
  出处：AGENTS.md 背景、rules.md §0.2

## 6. 工具与环境坑

- **Kimi Code 凭证 token 有效期仅 900s**
  脚本每次调用前重读凭证文件；401 鉴权波浪是常态，调用端必须有重试 + 缓存幂等。
  出处：AGENTS.md 环境、需求文档 §3
- **torchreid 的 PyPI 包名就是 `torchreid`，不是 deep-person-reid**
  隐性依赖 tensorboard 需补装；Market1501 权重（10.4MB）要按官方 MODEL_ZOO 另下载（自带只有 ImageNet 预训练），存 `models/osnet_x1_0_market1501.pth`。
  出处：docs/scorer-reid/spec.md 勘误、review01 附 Phase A
- **CPU 推理基线：双 YOLO 约 1.1s/帧（1920 宽 @imgsz1280）≈ 5.5s CPU/1s 素材**
  一场 2h 素材 ≈11h 后台；mot_cache 幂等可断点，别指望数量级提速。
  出处：需求文档 §3、主文档 §4
- **HF 下载必须走代理 `HTTPS_PROXY=http://127.0.0.1:7897`**
  CLIP/OSNet 权重首跑都要；pip 用清华镜像。
  出处：AGENTS.md 环境
- **Git Bash 下 python 打印中文必须先 `export PYTHONIOENCODING=utf-8`**
  出处：docs/batch2/spec.md Commands
- **VLM token 账本**
  K3 事件级协议 ÷2.4（443K 输入/113 事件）仍救不回性价比而下线；外部视频模型 ~15K token/段只适合小批量复核，不适于全量。
  出处：主文档 §8
- **跑批链条参数全靠显式传**
  gen_review_clips 漏 `--keep-clips` 就不产 events_index 与单事件 clips，下游全部断粮；mot_candidates/pilot_candidates 默认常量是旧测试路径，必须显式传 fid 与 --out。
  出处：docs/batch-speedup/spec.md F2

## 7. 流程与规范

- **四件套先行（spec/plan/todo/review）**
  scripts/tests 的非小修小补先产出四件套放 `docs/<功能名>/`，review 按轮次编号递增不覆盖；小修 bug、`work/` 下一次性探索可豁免。
  出处：AGENTS.md 代码规范
- **文档自审强制过 spec-reviewer**
  scorer-reid 一审抓出 3 个阻断问题（投票 None 票未定义、"零新调用"不可达、缓存迁移边界未定义）——契约完备性问题自查容易漏。
  出处：AGENTS.md、docs/scorer-reid/review01.md
- **降级出口要预先写进 spec**
  聚类纯度"不达标是基准情形"的预期管理应验（CLIP/OSNet 双双不达标）；写死降级路径（记 review、功能照上、指标转观察值）避免现场改目标。
  出处：docs/scorer-reid/review01.md、docs/scorer-cluster/spec.md
- **合集人工验收是最有效的纠错环节**
  批次 1 的同球重复、传球误标、弹出误标、锚点错位全部由立哥验收合集发现——每批都要过"标注 → 合集 → 验收 → 修 → 封存"完整环。
  出处：主文档 §4 批次 1
- **状态存 JSON 断点续做**
  goals/roster/mot_cache/vlm_cache/clip_cache 全部幂等落盘、原子写；11h 级长流程靠这个扛中断。
  出处：AGENTS.md 工作流约定、rules.md
- **目录治理：中间产物按场次归 `work/<场次>/`，archive/ 的 gitignore 要先行**
